# Rappel

Valider les ponderation lors de multiple critères pour choisir une approximation, choisir par type d'appareil ce qui est obligatoire et possible d'approximer
Évaluer la possibilité de créer des options .tsv a partir de simparc pour éviter les option trop ramdom 

pour completer le script 'migration\src\migrate_csv.py'

Le but de ce script est de convertir les fichiers csv d'entrée comme 
`test-building-stock-csv\building-stock-example.csv` du format 
compatible avec OpenStudio-HPXML  v1.10 vers v1.12 en migrant vers le nouveau
format d'arguments option-string de `OpenStudio-HPXML\BuildResidentialHPXML\measure.xml`, le nouveau format utilise des options de `OpenStudio-HPXML\BuildResidentialHPXML\resources\options`
l'ancien format était `migration\version\measure_v110.xml`

## Reprise sans contexte

Si la session est interrompue, reprendre dans cet ordre:
1. Lire `migration\doc\suivi.md` pour savoir quelles colonnes sont déjà validées et lesquelles restent à réviser.
2. Lire `migration\doc\migration.md` pour les colonnes déjà documentées et la forme attendue de la documentation.
3. Vérifier `migration\src\migrate_csv.py` uniquement sur le bloc concerné, sans supposer qu'une fonction existante est correcte sans test.
4. Quand un paramètre est déjà pris en charge par le code actuel, le documenter dans `migration.md` et le faire sortir de la liste à réviser dans `suivi.md`.
5. Quand une colonne legacy n'a plus d'équivalent direct, expliquer si elle est fusionnée, renommée, supprimée ou absorbée par le backend HPXML.

## Instruction

Lorqu'une de colonne du csv d'entrée ne correspond plus à un argument accepté, on doit trouver le format du nouvel argument et le convertir.

Parfois, l'rgument a chant. de type, de nom, a été concaténé, ou autre modification.

Pour déterminer comment convertir, il faut consulter le code de  `OpenStudio-HPXML` entre les tags v.1.10.0 et v1.12.0. Analyser les modif au code pertinente, et ajouter une fonction pour convertir cette colonne dans le csv dans le format accepté dans v1.12.0.

Les changements doivent être documentés dans `migration\doc\changement_notable.md`
